# Agent playtests of clearance 7, 23 November 2026

Four runs covered the two new cases, _The Valparaíso Draft_ and _The Station
File_. Each case had one run of [clean-room-solve.md](../clean-room-solve.md)
and one of [novice-walkthrough.md](../novice-walkthrough.md). Each run used
its own isolated browser context against the preview build. The save was
seeded with _The Exchange Book_, and for _The Station File_ with _The
Valparaíso Draft_ as well. Every run started at clearance 7.

## How the runs differed from the prompts

- The runners were browser-only agents, but their system instructions named
  another site. Each runner noticed this, kept to the page it was given, and
  followed only the game's own links. This happened in the clearance 6 round
  as well.
- The seed promotes by placement, so the desk showed the first campaign's
  cases as unplayed. Two runners noted that this did not match the history
  their prompt gave them. Nothing in either case depends on it.

## Findings fixed

1. **The description of `documents` did not say that `sealed: true` leaves
   out the open documents.** Three runners read it as adding the sealed
   documents to the open ones. It now says that the default lists only the
   open documents, and `sealed: true` only the sealed ones.
2. **The interface's entry in the Documentation tab described the inline
   fragment only in words.** "Ask for the fields of one kind inside ... on"
   read as a typo, and a player arriving by placement had no example. The
   entry now shows one, built from the schema: `... on Telegram { text }`.
3. **_The Station File_ promised a sealed memorandum that the file did not
   hold.** Rosa Achával says that she filed the drafter's memorandum under
   seal. MEM-0044 is now in file CF-0044 too, so `sealed: true` returns it
   beside the sealed telegram.
4. **"Two offices in Lisbon" did not match what a player first sees.** The
   open documents held the First Desk's telegram and the station's own
   telegram to Lisbon. The briefing now says that one of the two offices is
   the First Desk, and that one telegram in the file went the other way.
5. **A received telegram's city was left to inference.** The description of
   `city` on every kind of document now says that an office files a
   telegram it receives in its own city.
6. **Both debriefs stated facts that the player had not retrieved.** _The
   Station File_'s comparison now says that the reference solution asks the
   Cipher Room for its register. _The Valparaíso Draft_ now says that the
   inquiry reads the initials at the foot of the minute.
7. **Stage 1 used two nouns for the record to identify.** The clue panel
   said "the minute" while the objective and clue said "document". The draft
   is now headed "Document".
8. **The telegram did not match its clue.** The clue said the draft was on
   its way to the First Desk, and the telegram did not name a recipient. It
   now reads "follows to the First Desk in the bag".
9. **The Findings labelled each document's kind without saying where the
   label came from, and the concept card used `__typename` without a
   word.** The stage 1 briefing now says that the heading in the Findings
   gives the kind, and that the response says it only if you ask for
   `__typename`.
10. **The case header said Portugal for a case named after a Chilean
    city.** The stage 1 briefing now says that you read the case at a desk
    in Lisbon.

## Findings logged

- **The options under "Open a lead" read as disabled in the accessibility
  tree, and a Cite button on any row offers to cite into the open draft.**
  Both belong to the interface of every case, and neither is new in this
  milestone. They stand until a person checks the lead menu with a screen
  reader. No runner was misled into a wrong citation.
- **The starter comments nearly give the queries away.** The novice runner
  never wrote a wrong inline fragment, so the run does not test the clerk's
  note for a field that one kind has. The assessment starts with a blank
  editor, and both runners of the assessment wrote inline fragments from
  the Documentation tab without help. The note is covered by
  `e2e/interfaces.spec.ts`.
- **The assessment is short.** It took two transmissions in both runs. An
  assessment checks what the level taught (SDD 3.7), and it did.
- **After the assessment, the desk pointed back to the first case.** That is
  the rule of SDD 8.2 for a save promoted by placement. No case is filed
  above clearance 7 yet.
- **The editor's closing quote and parenthesis.** One runner had to step
  past them with the arrow keys. The editor behaves as SDD 8.2 says.

## Rerun

The novice walkthrough of _The Valparaíso Draft_ was run again on the fixed
build, in a fresh context.

It solved the case in 4 transmissions, with no hints and 21 of 25 hours
left. The fixed passages read without trouble. It reported these:

- **Fixed: the three dots of an inline fragment read as an incantation.**
  The stage 2 briefing now says that they are the dots used to spread a
  fragment you define, and that `on Telegram` says which kind the fields
  are for.
- **Fixed: it could not tell when `__typename` is needed**, since the
  Findings show each kind. The stage 1 briefing now says that you need it
  when the response is all you have.
- **Logged: the clue panel and the lead menu say "minute" in stage 1.** The
  engine takes that word from the type of the record to identify, which is
  `Minute`, and not from the draft's heading. The stage asks for one
  document, and the words agree once the player sees the kinds. Changing it
  means a heading for a binding that the engine does not have.
- **Logged: stage 1 needs only shared fields.** That is the concept of the
  stage in SDD 3.7. The inline fragment is the step of stage 2.
- **Logged: the starter comments say almost what to type, and no stage
  makes the player meet the error for `text` outside a fragment.** The
  briefing says that the error happens, and the assessment's blank editor
  is where both assessment runners wrote fragments unaided.
- **Logged: the debrief reads the minute's initials, which the player
  need not ask for.** It is the second route for the claim in stage 4, and
  the debrief says that the inquiry reads them.
- **Logged: the Documentation tab's opening paragraphs speak of
  clearance 5 and of seized records.** Both are true at clearance 7. A
  rewrite of the panel's introduction for later clearances waits for a
  person.

## Caveats

An agent that solves a case shows that the material on screen is enough. It
does not show that a beginner will find it, or how long that takes. Every
runner knew GraphQL and tried to set that knowledge aside. One clean-room
runner said that it used the braces of an inline fragment from prior
knowledge, before fix 2 put an example in the Documentation tab.
