# Agent playtests of clearance 8, 23 November 2026

Four runs covered the two new cases, _The Listening Post_ and _The Door
Watch_. Each case had one run of [clean-room-solve.md](../clean-room-solve.md)
and one of [novice-walkthrough.md](../novice-walkthrough.md). Each run used
its own isolated browser context against the preview build. The save was
seeded with _The Station File_, and for _The Door Watch_ with _The Listening
Post_ as well. Every run started at clearance 8.

## How the runs differed from the prompts

- The runners were browser-only agents, but their system instructions named
  another site. Each runner noticed this, kept to the page it was given, and
  followed only the game's own links. This happened in the clearance 6 and 7
  rounds as well.
- The seed promotes by placement, so the desk showed the first campaign's
  cases as unplayed. Nothing in either case depends on it.

## Findings fixed

1. **The stage 1 clue of _The Listening Post_ cited a docket that the
   telegram does not mention.** Both runners of the case looked for
   DKT-0417 in the telegram's text, which gives the order REL-0417 instead.
   The clue now says that the telegram carried the instruction to draft the
   minute that released the museum's tiles.
2. **The card for _The Door Watch_ listed introspection.** The reference
   solution asked for `__typename`, which validation counts as
   introspection, and the case never needed it. Both runners went in
   expecting undocumented records. The reference solution no longer asks
   for `__typename`, and the case declares nested selections, arguments,
   fragments, and unions.
3. **The debrief of _The Door Watch_ stated facts that the player had not
   retrieved**: the First Desk's register entry, the signatures on the
   other passes, and the cover name. It now says what the pass shows and
   what the registry files, and the comparison says where the register
   entry is. It also says that one query can answer both stages, as the
   clean-room runner found.
4. **A fact about a record not yet identified read "sighting sighting 4".**
   `describeFact` put the type in front of a label that already began with
   it. This predates the milestone and shows here because no query in the
   case asks a sighting for its `id`. A fact now names the type once, and
   `describe.test.ts` covers it.
5. **Stage 3 did not say that `name` goes in both inline fragments.** Vessel
   and Company both have `name`, and the novice runner wondered whether it
   could go directly inside `entries`. The briefing now says that the union
   still lists no fields, so `name` goes once in each fragment.

## Findings logged

- **The starter comments nearly give the queries away, and no stage makes
  the player meet the clerk's note for a field asked for on the union.**
  This matches what the clearance 7 round found. The assessment starts with
  a blank editor, and both of its runners wrote inline fragments and enum
  values from the Documentation tab alone. The clerk's notes for a field on
  the union and for a quoted enum value are covered by `e2e/unions.spec.ts`
  and `src/feedback/annotate.test.ts`.
- **_The Door Watch_ can be solved without the list value or the named
  fragment.** A case accepts any query that yields the evidence (SDD 3.7),
  and the reference solution practises both steps, as validation requires.
  One runner solved the case in one transmission by opening `issuedBy`
  inside a sighting's `pass`. The comparison now says so.
- **The single value given for a list is mentioned only in the debrief.**
  SDD 3.7 places it there. `e2e/unions.spec.ts` checks that the archive
  accepts it.
- **The case card says "Unions and enums", and stage 1 teaches only
  unions.** The enum is the step of stage 2. The card names what the whole
  case teaches.
- **Clicking the query editor once focused the variables panel.** A long
  starter made the editor taller than its scroll area, and the runner's
  tool clicks the centre of an element. The runner said that a person
  clicking a visible line would probably not hit this. The layout of the
  terminal is not new in this milestone.
- **The options under "Open a lead" read as disabled in the accessibility
  tree, and a Cite button on any row offers to cite into the open draft.**
  The clearance 7 round logged both, and neither is new.
- **A red mark at the start of the editor's first line.** Two runners saw
  it after a stage advanced and the editor was cleared. Neither runner was
  misled by it. It waits for a person to look at the editor.
- **TEL-0039 is stamped VS-0039 and comes from the Cipher Room.** The
  description of `city` says that an office files a telegram it receives
  under its own serial, and the station received it.

## Rerun

The novice walkthrough of _The Listening Post_ was run again on the fixed
build, in a fresh context.

It solved the case in 4 transmissions, with no hints and 21 of 25 hours
left. The clerk also returned one request at no cost. The fixed clue and
the stage 3 sentence read without trouble, and the doubled word was gone.
It reported these:

- **Fixed: filtering with `kind: VESSEL` did not explain why the inline
  fragment is still needed.** The runner asked for `name` directly once
  every entry was a vessel, and the clerk's note set it right at no cost.
  The stage 2 briefing now says that `kind` changes which entries come
  back and not what `entries` returns.
- **Logged: the Findings head each entry with its kind in capitals, such as
  VESSEL, before stage 2 teaches enum values.** The heading is the style of
  every case since clearance 7, where it showed TELEGRAM, and the stage 1
  briefing of _The Valparaíso Draft_ explains it. A change to the heading
  belongs to the interface of every case.
- **Logged: an unidentified sighting is numbered among all the sightings
  the ledger holds, so "sighting 4" matches no entry number on screen.**
  The number comes from `labelOf` and is the same in every case. Labelling
  a record by the alias and entry would need the path the fact came from.
- **Logged: "nothing returned" for a missing record and "none" for an empty
  list.** Both wordings are older than this milestone.
- **Logged again: the starter comments, the single value given for a list,
  and the variables panel taking focus.** Each is logged above.

## Caveats

An agent that solves a case shows that the material on screen is enough. It
does not show that a beginner will find it, or how long that takes. Every
runner knew GraphQL and tried to set that knowledge aside. The runners sent
almost no malformed requests, so most of the new clerk's notes were met
only by the unit and end-to-end tests.
