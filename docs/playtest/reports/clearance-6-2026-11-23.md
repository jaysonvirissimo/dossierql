# Agent playtests of clearance 6, 23 November 2026

Four runs covered the two new cases, _The Sealed Cabinet_ and _The Exchange
Book_. Each case had one run of [clean-room-solve.md](../clean-room-solve.md)
and one of [novice-walkthrough.md](../novice-walkthrough.md). Each run used
its own browser context against the preview build. The save was seeded with
_The Registrar's Return_, and for _The Exchange Book_ with _The Sealed
Cabinet_ as well. Every run started at clearance 6.

## How the runs differed from the prompts

- The runners were browser-only agents, but their system instructions named
  another site. Each runner noticed this, kept to the page it was given, and
  followed only the game's own links.
- Two runners resized the viewport. Every runner had trouble focusing the
  editor, and one sent an unchanged starter query because of it, at a cost of
  one hour.

## Findings fixed

1. **Stage 2 stalled on a citation that nothing asked for.** Each claim
   about docket DKT-0417 also needed the docket's `reference` row. The
   draft said only that the claim needed "more facts that connect to this
   one". The novice took a hint and found the row by guessing. Every
   cabinet claim now rests on the field that answers it. The other dockets
   were refiled, so the First Desk minuted only DKT-0417, and nothing but
   DKT-0417 can support those claims.
2. **The briefing said one field of `Query` was missing; two are.** The
   stage 1 briefing, starter comment, and hint now name `cabinet`, and say
   that the other field belongs to a later case.
3. **A weight of 0 looked like a failure.** The label now says that the
   request asks for no records, and that introspection and `__typename`
   weigh nothing. The glossary entries for request weight and
   introspection say so too.
4. **Nothing outside the teaching case said how to read a field's type.**
   The clean-room runner of the assessment probed the archive with free
   errors to learn types. The glossary entry for introspection now shows
   `__type(name: "Query")`, `type { kind name ofType }`, and `__typename`.
   A player who comes to the assessment by placement reads it there.
5. **`opened` and its scalar were never explained.** The stage 3 briefing
   now reads the value FS-0088 through the description of `DeskSerial`.
6. **Stage 3's type query already answers stage 4.** The stage 4 briefing
   now says that a player who read the types has seen the answer, and that
   `__typename` gives it from inside the response.
7. **The draft for stage 4 was headed "Held for".** It is now headed
   "Operative", like the other stages, which are headed by the record's
   type.
8. **The stage 2 dispatch asserted what the mark did.** It now says that the
   mark on the docket is the Fourth Desk.
9. **The assessment's debrief stated facts that the player had not
   retrieved.** It now says that the inquiry reads the rest of the slip,
   and the comparison says why the reference solution asks for sightings.

## Findings first logged, and fixed afterwards

These findings were logged when the report was first written. All but the
last were fixed in a second pass, listed under "Second pass" below.

- **A whole `__schema` result is long to read in the findings.** It lists 38
  types. Both runners' tools failed on it.
- **Stage 3's type query is not strictly needed.** A player can guess that
  `copiedTo` holds offices and ask for `name`.
- **A Cite button can name a lead whose identifying field was not asked
  for.** After `heldFor { __typename }`, the button already read "into the
  draft for GILT_MAGPIE".
- **Interface behaviour seen again:** deeply nested values wrap narrowly in
  the findings; Cite labels name the path only when the path carries facts;
  identical errors are shown once; a free rejection appears above the
  previous findings. One runner reported that the options of the lead menu
  are exposed as disabled in the accessibility tree.
- **No technique note at clearance 6.** Introspection has no kata yet
  (SDD 3.11), so the debrief says nothing about technique. This one stays
  open as a design item, not as a fault on screen.

## Second pass

Every finding logged above was fixed, except the kata:

- **Introspection results have a compact view.** A long list of types
  folds to one line a type, such as "Query · 16 fields" or "String · no
  fields: holds a single value". Each field takes one line, with its type
  read layer by layer, outermost first. Field names appear as the query
  wrote them, so `ofType` is no longer "of type". The view says that it
  holds no evidence and has nothing to cite. A record asked only for its
  `__typename` is headed by that type, not by "record".
- **Stage 3 needs its type query.** `Docket.copiedTo` is now
  `circulation`. The name does not say whether the field holds office
  names or office records, and the briefing says that the type decides how
  to ask. The briefing, the starter, and the legend use `[TransferOrder!]!`
  as their example, so they no longer give the answer.
- **A lead that no query has identified is numbered, not shown by its filing
  key.** It reads "operative 1, not yet identified" until a query returns
  its codename. Dockets and slips are identified by their `reference` and
  `number`, register entries by their serial, and drawers by their label.
- **Findings rows wrap.** The Cite button moves to the next line before the
  value can be squeezed. Nested rows are indented less.
- **Cite controls.** A row whose field returned nothing offers no Cite. Every
  button is labelled with the row's own fields, so rows of the same shape
  read the same. The facts the citation carries are in the button's title
  and in the message after citing. A row outside every lead still enters
  the open draft. Marking it would show which rows are evidence, so SDD
  3.2 now states that rule.
- **Errors made in several places** are shown once, with every place.
- **A returned request** now says that the findings beneath it are from an
  earlier transmission.
- **The lead menu** was checked in an end-to-end test. Once a lead has been
  retrieved, the menu and its options are enabled, so the report came from
  the runner's tools.
- **The editor** steps over the closing brace it added when a player types
  one on its own line, and Enter no longer accepts a suggestion that the
  player did not pick. The clerk's note on a closing brace too many says
  that the editor adds them.
- **Clues** now open with a sentence saying that each clue is a fact about
  the record the stage asks for, in every case.

## Second rerun

The novice walkthrough of _The Sealed Cabinet_ was run a third time, after
the second pass. The runner solved the case in 8 transmissions against the
reference solution's 7, with no hints and 25 of 33 hours left. It could say
why each query had its shape, except that it asked for `ofType` three times
because the text said so. The result then showed it why. Fixed after this
run:

- The first briefing says what a type is, and that `cabinet` takes no
  argument.
- The stage 3 briefing says that one `ofType` too many does no harm. It
  introduces the paragraph on `opened` as one that the stage does not need.
- The introspection legend speaks of layers only when the response holds
  a type reference.

Logged from this run:

- Stage 4 is still easy to answer before `__typename` is asked: the
  type query of stage 3 shows `heldFor` as an operative, and the clue
  sentence and lead menu say "operative". `__typename` matters most where
  a field can return more than one type, which clearance 8 introduces
  with unions. Stage 4 keeps the step, and its briefing says plainly that
  the player may have seen the answer.
- Findings show field names as words ("held for"), as they do in every
  case. The introspection view shows them as typed.
- The "Not yet opened" lines are long under nested records. They are how
  the findings teach that a result can be opened further, in every case.
- Once, typing into the editor had no effect after the starter query
  changed between stages. The runner used the automation tool to set the
  text, and the end-to-end tests type into the editor without trouble, so
  this is unconfirmed.

## Caveats

Every runner already knows GraphQL. The clean-room runs show that the
material on screen is sufficient. They do not show that a beginner finds it,
or how long it takes. The runs measure transmissions, not minutes.
